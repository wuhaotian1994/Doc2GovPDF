# 定时 Agent → 微信小绿书草稿

每封邮件生成一篇微信公众号“图片消息”（article_type=newspic）草稿，只入草稿箱，不自动发布。

## 发邮件

- 发件人与收件人沿用已经配置的邮件到公众号流程，实际地址见交付聊天或私有模板包。
- 主题：`[WX-NEWSPIC] 你的标题`
- 邮件正文：`小绿书文案与图片见附件，请写入草稿箱。`
- 附件：UTF-8 编码的 `article.md`，以及其中 `images` 列出的全部 JPG/PNG 图片。不要发送 ZIP、网盘链接或邮件内嵌图片。
- `article.md` 的 title 是草稿标题，邮件正文不进入草稿。

## 填写模板

复制同目录 `article.md`，替换编号、标题、图片清单和配文。

| 字段 | 要求 |
| --- | --- |
| article_id | 稳定唯一编号，最多80字符，只用英文字母、数字、点、短横线、下划线。建议日期-选题-newspic-v1。 |
| title | 必填，最多32字符；建议20字以内，直接点明读者能获得什么。 |
| images | YAML有序列表，1—20张；每行是一个双引号包围的附件文件名。第一张就是封面。 |
| 第二条 `---` 之后 | 小绿书配文，纯文本，保留换行；不要写HTML、Markdown图片、链接语法、表格或代码块。 |

图片按 images 列表顺序展示，与邮件附件排列或文件名排序无关。不另填 cover、author、digest 或 source_url；所有附图均需列入 images，禁止重复文件名和重复引用。

本流程将配文限制为1000字符以内、UTF-8编码不超过2048字节，建议500汉字以内；这是兼容性保护限制。普通 `#话题` 作为文本保留，不保证成为微信可点击的话题标签。

## 图片与内容建议

建议准备3—6张3:4竖图，如900×1200：首图写一个清楚的结论，中间每图讲一个重点，末图给出可执行建议。此比例是创作建议，不是接口硬性要求。

单图最大10MB，附件总计最大20MB。流程会按原比例缩至最长边1600像素，并转换成不超过1MB的JPEG；透明部分变白。请使用清晰图片，把关键文字放在安全区域内。流程只上传邮件里的成品图，不代替 Agent 生成图片，也不下载远程图片。

## 重试、修订与检查

- 相同 article_id、相同内容重复发送，不重复创建草稿。
- 改了配文、标题、图片或顺序，必须更换编号（如-v2）；生成新草稿，不覆盖旧稿。
- 图片缺失、超量、损坏、字段错误时拒绝创建；在n8n的Executions查看原因，修正后重新发送。
- 微信新增请求结果不明确时停止自动重试，需要先核对草稿箱。
- 邮件保留未读，处理进度按UID追踪；把旧邮件改回未读不能保证重试。
- 没有成功/失败回执邮件。入库后到公众号草稿箱预览，确认图片裁剪及文字再自行发布。

## 可直接交给定时 Agent 的指令

按本规范完成一篇微信小绿书。先写标题与简短配文，再准备完整图片；用article.md记录唯一article_id、title和有序images列表，第一张图作封面。用普通附件一次性发送article.md及所有图片，主题以[WX-NEWSPIC]开头。不要把模板包ZIP作为邮件附件，不要发送占位图或缺图稿。传输重试沿用原编号；修改内容递增版本。不要将密钥、任务日志、私有资料或邮件签名写入article.md。只要求进入草稿箱，不要求发布。

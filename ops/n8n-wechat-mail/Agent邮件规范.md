# 定时 Agent → 微信公众号草稿

收件人、允许的发件人请按本次聊天约定配置，不要将 AppSecret 或邮箱密码放入邮件或文章。

每封邮件对应一篇图文草稿，只入草稿箱，不自动发布。

## 邮件格式

- 主题：`[WX-DRAFT] 文章标题`
- 邮件正文：可写“文章和配图见附件”，正文不参与文章解析。
- 必需附件：UTF-8 编码的 `article.md`，以及 YAML 中 `cover` 指定的封面文件。
- 配图：与文章一起作为普通附件发送。支持 JPG/PNG，不用压缩包、网盘、远程图片 URL 或邮件内嵌 HTML 图片。
- 文章中的 `![配图说明](images/figure-01.jpg)` 对应同封邮件中名为 `figure-01.jpg` 的附件；`images/` 是文章引用前缀，不需要创建文件夹。
- 每封邮件附件文件名不能重复；最多 22 个附件，总计不超过 20 MB，单张图片不超过 10 MB。

## article.md 元信息

请复制同目录 article.md。开头的两行 `---` 及它们之间的字段不能省略，所有字段值用双引号包围：

| 字段 | 规则 |
| --- | --- |
| article_id | 必填，唯一编号，例如 `2026-10-28-ai-daily-v1`。只用英文、数字、点、短横线、下划线，最多80字符。 |
| title | 必填，最多64字符。 |
| author | 可选，最多8字符。 |
| digest | 可选，最多120字符。 |
| cover | 必填，填写封面附件完整文件名，包括扩展名。推荐900×383，重要内容居中。 |
| source_url | 可选，空字符串或合法http/https原文链接。 |

## 正文与图片

支持段落、二至三级标题、粗体、斜体、引用、列表、代码块、简单表格及配图。不要使用脚本、iframe、自定义CSS或依赖网页交互的内容。公众号可能自行调整链接和样式，最终以草稿预览为准。

图片会转换为微信使用的JPEG，最长边1600像素、单张不超过1MB；透明部分会变白。图片先上传微信，再替换正文链接。表格尽量不超过3列，代码行不要过长。

## 去重与错误

- 同一 article_id、同一内容重复发送，只保留第一次创建的草稿。
- 修订稿请更换编号，例如 `-v2`；会新增草稿，不覆盖旧稿。
- 缺少封面、配图或字段不合规时，流程失败，不创建文章草稿。查看 n8n 的 Executions 了解原因。
- 邮件保留未读状态，流程按 UID 记录处理进度。处理失败后请在 n8n 重试该执行，或重新发送修正邮件；仅改回未读不会保证重试。
- 如果微信新增草稿请求的结果不确定，系统停止自动重复新增，需先检查草稿箱。
- 本流程不发送成功/失败通知邮件，也不会自动发布文章。

## 给定时 Agent 的指令

按本规范生成一封邮件。先完成文章、封面及所有配图，检查 Markdown 引用与附件文件名逐一对应，再一次性发送。每篇使用稳定且唯一的 article_id，传输重试沿用原编号，内容修订递增版本号。只将文章 Markdown 写入 article.md；不要把工具日志、任务说明、密钥、邮件签名写入正文文件。发送前确认附件齐全，尤其不要忘记封面。

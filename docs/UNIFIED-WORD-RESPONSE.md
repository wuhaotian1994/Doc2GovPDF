# 统一Word工作区与原文件流转

新建填写和打开原生Word现在进入相同的三步工作区，使用同一套核对、保存、恢复、预览和下载操作。高校办公室收到含横向附件的Word后，无需进入另一套界面或重录内容。与此同时修复了本次官方原件转PDF丢失正文方向、单元格边线和底色的问题。

这是PR #5分支实施者的知情岗位验收，不是独立首次使用者签收，也不是全文国标通过声明。最新P0全文标准合同、本机字体授权/真实身份/嵌入链路、文号建议交互及完整反馈闭环继续保留待办；不以本轮原件保护替代它们。

## 现状、缺口与结果

旧首页只接收填写草稿，原生Word在独立advanced页面。旧引擎仅记录末节页面，官方文件前三页正文也被按横向输出；单元格自身定义的边线/底纹没有进入PDF模型。

- 顶部“打开文档”和原页脚入口直接在当前页面接收DOCX、文字材料及填写/Word恢复稿。原填写稿保留，“我的文档”可继续，两者之间不靠下载搬运。
- 原Word按原段落和原生表格编辑文字；段落格式按需展开，文字/格式可撤销。合并格、行列和分节保持；含域、链接、已有修订等受保护段落明确只读，不静默压平。原文字体/日期/署名位置不被新表单猜填。
- 原件另存不覆盖。未修改官方Word的下载与输入逐字节相同；修改后的文件保留原包其他所有部件，仅原正文XML相应段落改变。
- 原件保护、工作稿另存与规范化分别说明。PDF实际字体降级在页面可见，导出前核对当前预览；备用草拟不等于全文标准通过。原Word仍依赖接收端字体，跨机器可能重排。
- 源模型按区块记录分节，PDF切换真实纸张方向和边距。读取每格四边线及纯色底纹，保留原合并关系和空白填写空间；不把所有原表强制画成同一种网格。
- 不支持的连续/奇偶分节或特殊线型不生成冒充成功的PDF；在同一工作区说明具体边界，原件/Word另存仍可用。另以明确合成的连续分节变体实际验证了此路径。

## 历史任务与恢复

旧advanced链接由小型承接页进入同一首页，未嵌旧UI。旧IndexedDB工作稿在取得旧编辑锁后读取为独立工作稿，不删除旧记录。迁移标记使重复访问旧链接继续新修改，不用旧快照回滚；旧源模型仅在来源、ID顺序和原末节页面匹配、未规范化时补齐原节信息及新读取的格线/底色。

旧未完成填写任务保留完整原字段，在相同基本信息区域补齐标题/正文后继续；旧文种、单位、日期、附注和抄送值不要求重录。旧字体配置随工作稿保存，当前填写稿与原Word各自配置不互相覆盖。未改变且重新匹配的判断才承接，相关文字、段落格式、依据或版本改变重新核对。

Word记录与不可变原件另设命名空间，旧页面的清理操作不会删除新工作稿原件。正常填写草稿仍兼容原v1–v5；Word恢复包包含原件、结构、判断及选择的字体字节。不同模型留在实现内部，不要求用户理解它们。保存失败保留在内存并阻止切换，不静默淘汰超过上限的稿件。

应用模块失败时，HTML内独立保护脚本仍能从本地读取Word工作稿和原件，下载恢复包；不会让用户误以为正在编辑另一个普通表单。损坏文件不替换当前稿，错误在当前页面和打开的弹窗中都可见。

## 两个完整岗位任务及证据

原生文件来自[河北师范大学2026年7月10日实验室安全通知](https://jsc.hebtu.edu.cn/a/2026/07/10/D21574AE585A482097C6BEA4A36D3BFF.html)的[官方DOCX](https://jsc.hebtu.edu.cn/dynamic/download.jsp?id=8bb130db6e3c4b1da20dc8f4354f25c4)。38431字节，SHA256 `bae60c771f57218b93d2b383d08a26ac025a119b872ca634e01630382a2230b1`；103个段落，两原生表（6行/7逻辑列、4行/9列），两节。原件不提交到Git，公开来源与校验和用于复现。

| 任务 | 实际结果 |
| --- | --- |
| 从空白编制虚构高校通知，原位加3×2表 | 标题、正文、6格、署名日期保存/导出；Word和PDF均1页 |
| 接收官方原Word，原样另存 | Word原字节相同；PDF5页，前3页纵向595.3×841.9pt，后2页横向841.9×595.3pt |
| 改标题和原格、撤销、保存关页重开再另存 | 仅两处模拟文字变化；103段、两表、两节、原署名日期及其余包部件保持 |
| 从旧链接承接、继续修改、重复旧链接 | 原修改保留，原方向和格线/底色恢复；不重录、不回滚新修改 |
| 继续旧未完成任务 | 原单位/日期/附注/抄送保留，补正文后在同一工作区完成Word/PDF |

三浏览器Chrome、Firefox、WebKit的主任务各18项，共54项通过，1280×720及1280×600桌面。另有原有启动保护三浏览器33项、相关Node32项、四个新增Go分节/格线测试及全量`go test ./...`、`go vet ./...`通过。之后仅细化“不支持PDF”的空态文案；最终实际4173正例6项、连续分节负例3项对该最终资产复核，不把前一轮54项冒充文案改后全量重跑。

共15组实际Word/PDF、51页直接PDF文字全量核对；每组原件哈希、段落顺序、修改范围、源包部件、方向、PDF线与底色分别验证。官方两附件各有142/144个线对象和7/9个填色矩形，空格仍有边界。隐藏Microsoft Word 16.0只读渲染5份代表共17页，绑定实际文件SHA与COM正文逻辑SHA；全部34页Word/直接PDF（24张不同页图）已查看。字体、断行和分页位置有差别：未修改源PDF第3页主要为署名日期和附件说明，窄原格添加模拟文字会纵向换行，Word亦保留原窄格；不宣称逐像素、逐行或正式印发级保真。

Word导出PDF的部分字体ToUnicode文本抽取异常，但实际可见中文正确；本轮未将乱码抽取当产品正文丢失，改用Word COM逻辑正文SHA、源DOCX XML和真实页图交叉验证。直接PDF仍独立核对全文。网络证据首轮受Worker结束后调试缓存回收影响，改沿用已有route.fetch记录真实响应并原样交给Worker，不替换引擎字节。连续分节夹具初次重序列化更换了XML前缀，触发既有前缀兼容边界；改为只插入分节类型验证目标路径，未冒称已扩展任意命名空间支持。

## 运行与边界

本地固定服务为`http://127.0.0.1:4173`，仍是本聊天隐藏回环进程，PID以状态文件为准；本次原样复制QA资产，无提交后重建另一份Wasm。`headAtCheck`记录检查时checkout，不证明源码已提交，精确关系看源文件/资产SHA。实际服务的Word与官方源字节相同，PDF方向/格线/底色复核通过。服务不依赖测试浏览器，不抢前台，未配置Windows开机自动启动。

本轮不是完整Word编辑器：原Word不能随意增删结构，受保护段落不做局部篡写；连续/奇偶分节、图案底纹和特殊格线不能假装支持。原表的细节/页眉页脚复杂变体仍按实际支持边界判断。旧独立PDF核对等专用工具尚未搬入新壳，历史源码与数据保留，不宣称历史高级工具全集已迁完。后续在同一工作区按实际任务继续承接，不恢复第二套产品。未验证真实中文选词、手机/真机Safari、物理打印或任意Word保真。

复现入口为`scripts/test-writer-unified-word.mjs`，可用`WORD_SOURCE`指定上述原件、`WORD_PROFILE`选择浏览器；构建目录`build/qa/unified-word-web`。独立核验用`scripts/verify-unified-word.py`、隐藏Word用`scripts/verify-unified-word.ps1`、全页渲染用`scripts/render-unified-word-pages.py`。负例夹具生成/验收与固定服务冒烟脚本同目录，均只处理本地副本。后续P0标准合同、字体授权与真实映射、建议交互及完整反馈继续同一个PR，不默认合并或部署。

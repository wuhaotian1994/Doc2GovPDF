# Doc2GovPDF 交互参考与设计约束

日期：2026-10-14。产品决策：Windows 桌面工具形态；[Squoosh](https://squoosh.app/) 只作为文件处理流程参考，[ImageOptim](https://imageoptim.com/mac) 作为专注、紧凑的工具形态参考。界面遵循 Windows 操作习惯，并使用 Impeccable 检查设计质量。

## 产品本质

用户要完成的是“把手上的内容变成可以交付的公文”。软件承担文件接收、格式整理、质量检查和成品输出；用户只处理需要自己判断的事项。因此，核心体验应是一个短流程的文件加工工具。

公文与图片的差异在于，错误的文字或数字修改可能改变原意。简洁不能以隐藏问题为代价：能可靠处理的格式自动完成，涉及内容的修改可确认、可撤销，未能检查的范围必须明确。

## 为什么选择 Squoosh

Squoosh 官方首页给出的流程是打开图片、查看差异、保存，并允许进一步调整设置；其图片处理在本机完成。[官方首页](https://squoosh.app/)

这与本项目有相同的任务结构：一个输入文件、一套专业处理、一个可查看的结果、一次明确的输出。用户不需要先理解处理引擎，结果本身就是工作中心。这里的“轻巧”首先指操作负担；不据此推断 Windows 应用的安装体积或内存占用。

ImageOptim 的紧凑桌面形态适合本项目，但其默认原地覆盖文件的行为不适合公文。因此只借鉴专注和低操作负担，保留我们自己的预览、确认和另存流程。[ImageOptim 使用说明](https://imageoptim.com/howto.html)

## 交互映射

| Squoosh 的任务方式 | 本项目对应体验 |
| --- | --- |
| 直接打开、拖入或粘贴图片 | 首页直接拖入 DOCX、选择文件或粘贴正文 |
| 围绕处理结果查看变化 | 文档预览占主要空间，问题与对应原文关联 |
| 查看原图与结果的差别 | 按需查看原文、修改后文字和格式调整摘要 |
| 可以进一步调参数 | 文种和单位预设可见，专业排版参数收进高级设置 |
| 保存当前结果 | 明确的“导出”主按钮，默认提供 DOCX 与 PDF |

## 首页与工作页

首页只承担接收内容的任务。中央提供“拖入 Word 文件，或粘贴正文”，同时保留“选择文件”按钮，照顾不熟悉拖放的用户。辅助入口为“从模板新建”；最近文件可折叠，设置放在次要位置。

收到文件或正文后直接进入同一工作页，展示解析和检查进度。模板新建通过少量必要字段接入同一流程。文种识别不确定时用一句话让用户选择；不确定的标题和正文结构不能静默确定。

工作页以成品预览为中心，旁边展示问题摘要。首先告诉用户“还需核对 2 处”，再提供问题列表。点击问题定位原文并显示原因和可采取的操作。高级条款依据按需展开。没有阻断项时突出“导出”；有问题时突出“查看问题”，同时允许保留草稿。

修改前后对照按需打开，不能照搬图片的滑动对比。公文重排后页码、换行会变化，应以段落和修改点定位，避免左右两页对不上。

## 界面约束

1. 同一状态只突出一个主操作，导入后不要求再点一次“开始机检”。
2. 默认值覆盖常规出稿；单位信息首次填写后可复用，不让用户输入毫米、磅值或字体内部名称。
3. 主界面不放统计大屏、功能九宫格、规则配置表或营销内容。
4. 用“有 2 处数字需要核对”等普通话描述任务；详细规则编号保留在详情中。
5. 状态使用文字与图标共同表达，不能只依靠红绿颜色；支持键盘、Windows 缩放和较小屏幕。
6. 文件始终在本机处理；原文件不覆盖，修改可撤销，草稿自动保存。
7. Squoosh 的图片处理本地化不等于完全没有联网行为，其仓库说明存在分析统计；本项目不继承该做法，默认不收集使用统计。[Squoosh 隐私说明](https://github.com/GoogleChromeLabs/squoosh#privacy)

## 原型验收

原型至少覆盖空白首页、处理进度、正常结果、有待核对问题、导出成功和失败恢复六种状态。首次使用者应能无需讲解找到导入、定位问题和导出；后续通过至少 5 名非技术用户任务观察验证，不以界面好看代替好用。

这里采用的是公开产品的任务流程与官方说明；参考软件的体积和性能不作为本项目指标。当前实现状态与验证结果见 [开发记录](STATUS.md)。

## 2026-10-18 网页版重做

用户要求充分应用已确认参考并废弃旧 UI。Squoosh 的直接输入与结果画布成为主要结构依据，ImageOptim 提供低操作负担的原则。实现为浏览器本地 Go/Wasm 工具，使用新的莓红/粉色/温白视觉系统和独立 web/ 源目录。旧文档上方关于“Windows 桌面形态”的决定仅表示 2026-10-14 时的历史选择，已由当前要求取代。详见 WEB-2.0.md。

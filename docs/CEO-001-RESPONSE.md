日期：2026-10-21。状态：实现完成，提交 PR 后等待 CEO 评价，不自行标记 CEO 议题已关闭。

## 先回应现状

原有三步填写已经把提醒放在导出前，错误必须修改、需要判断的项目可以保留原文、建议不阻断下载；引擎也已提供原文、建议文本和依据。这些行为保留。

缺口是用户只看到 message，返回后仍要在长正文中自行寻找；部分 message 没解释具体规则；任何修改均清空确认，而且问题 ID 含全文摘要，改标题也使正文提醒得到新 ID。本轮围绕这些缺口改进现有流程，没有增设报告或规则管理界面。

## 完成行为

- 每条提醒显示等级、所属字段/段落、对应的完整原文。必须修正在前，其次需要判断，最后是不影响下载的建议；依据和建议写法渐进展开。
- “定位到原文”回到对应填写字段，展开原本折叠的选填项，选中准确的那一段；正文内部滚动到所选位置，并提供返回提醒的入口。重复文本按实际段落分别定位，不使用全文首次命中查找。
- 需要判断的项目可手动保留原文；确认绑定当前文档、原文段落、规则、解释、建议、依据和段落格式。改标题或增添无关段落后，未受影响的确认映射到最新引擎 ID，真实 Word/PDF 导出仍接受它。
- 原文或判断依据改变，确认撤销；检查时过期提醒不可继续确认。新建/导入另一文档不继承判断。编辑后又撤回也不自动恢复先前确认。
- 现有规则的笼统修正文案改为复用具体规则解释；用户对照建议自行决定，检查和定位均不自动改写正文或数字。

## 明确边界

确认的最小上下文目前是一个输入段落；修改同一段落内的其他句子也需要重新判断该段。跨段数字/全篇结构规则和未分类规则保守依赖整稿，相关内容变化会重新核对。完全相同的段落数量或相邻上下文变化时也重新核对，避免把一处判断转给另一处；未承诺任意重排情况下都保留确认。

确认仅在本次打开的文档会话中保留，不跨刷新持久保存。提醒没有自动应用建议，错误不能用确认绕过；TXT 仍允许保留原始内容。既有文档字体不支持 emoji U+1F600，预览会明确失败并保留草稿，本轮没有扩展该字形支持；UTF-16 偏移由独立逻辑测试覆盖，不等于 emoji PDF 导出验收。WebKit 是测试引擎，桌面验证不等于真机 Safari 或手机验收，也没有真实目标用户的耗时研究。

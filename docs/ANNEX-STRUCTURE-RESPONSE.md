# 实际附件身份、起页与有效确认保留

招生经办人现在可以在材料核对中明确声明“这是实际附件”，或在同稿段落编辑中确认原附件标识与标题。后续保存恢复、预览与实际Word/PDF/TXT保留该身份：附件另面起排，标识/标题按相应角色编排，页码连续，并核对名称、顺序号与正文附件说明的对应关系。

本轮回应CEO提交`e13c16d13a67a6f7cc5aaf604d8ce7a9b18e8972`的P1实际附件与P2位置变化失选，同时开始落实P0的[内部标准覆盖合同](STANDARDS-COVERAGE.md)。全文真实字体链路与全部标准覆盖仍未完成；此文不是全文合规声明、独立盲测签收或主线已集成证明。

## 现有断点与实现

原材料确认只有正文与落款后区域，实际附件随区域被当作普通附注；生成稿的表格可以紧跟署名日期，未另面。表格选择键又含所在区域，从正文变为日期后时，即使同一原表完全未变也会失选。

- 材料中仅对已有独立“附件/附件1”等原标识及已有标题提出身份确认，默认不选。正文内表格和普通说明不自动成为附件，不猜造名称、序号或缺失文件。
- 同稿编辑可声明、取消及撤销。标识/标题的锚点绑定原段落，受语义约束的格式有明确说明；仍在相同工作区，不靠手工分页参数或另一套高级页面。
- 编译器保留原字句与网格，声明附件后另面起排，标识顶格、标题居中，按第一/第三行关系生成间距；多个附件分别起页。普通落款后内容不再整体称为附注。
- 引擎只对明确声明的生成稿附件检查：名称/序号与说明对应、另面、标题位置、有效内容及多附件编号。名字不对应等错误不能用“确认保留”消掉；可以保存工作稿继续修改。原件保护不因此被强制当成规范化。
- 表格选择改为绑定原格内容、出现位置及重复数量，不绑定正文/落款后区域。纯位置变化保留选择；原范围、内容或独立行关系真正变化时明确说明原因、要求重新判断，不悄悄沿用或取消。
- 草稿v6保存附件锚点，兼容原v1–v5。复制、归档、下载、启动失败应急备份及启动前新输入恢复均保留结构；缺失锚点不静默降为文字。TXT也按明确附件语义保留署名日期后的顺序。

## 字号与列宽的取舍

本轮不把“页数少”作为成功。明确实际附件的标识/正文和表格请求16pt，标题请求22pt；这是字号与角色请求，实际字体类别仍须独立核验，备用Noto不等于仿宋/黑体/小标宋。

必要实页检查发现：改成相应字号后，沿用按14pt分配的列宽，会让最长校名和一条公费备注的最后一字换行。因此补了按实际请求字号计算的列宽需要，优先保住数据内容空间，必要时让列标题合理回行；没有缩字、压行距、改人数或强塞一页。普通业务表和空白回执原行为保留，原生Word不走此推导。

本机招生稿Word/PDF均为3页：正文/原署名日期/公开说明在第1页；附件标识、居中标题、表头及1–11校在第2页；第3页重复表头后有第12校与合计9000。合计有所属数据可核对，所有校名及两条公费备注完整单行。不能将旧两页正文混排稿当成更符合，也不承诺其他输入或电脑仍为三页。

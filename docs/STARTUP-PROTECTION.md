# 下一步清空问题：启动保护

日期：2026-10-21。起点：用户截图和实际反馈，基线 2838a7e。

## 已复现的漏洞

旧页面把 PDF.js 静态导入与填写逻辑放在同一个模块链上。预览依赖缺失、加载失败或主模块尚未就绪时，表单的 submit 拦截尚未注册，但“下一步”仍是原生提交按钮。点击会发起 GET 导航，把字段放入地址栏，再显示空表单。

独立无头 Chrome 对旧版分别阻断 PDF.js 和延迟 write.js，均复现一次导航、字段清空、无法进入正文。此前正常流程测试等待 writerReady 后才操作，没有覆盖此时段；其通过不能证明启动失败时不会丢输入。

## 修复行为

- 构建时将轻量保护脚本内联到 HTML，先于应用模块阻止原生表单提交。
- 下一步使用普通按钮；单行字段回车使用相同保护流程，中文输入法组合提交不会推进步骤。
- 表单填写和导航独立于预览模块；预览依赖按需加载，失败时保留填写及文字/草稿下载。
- 应用加载期间的输入保存在当前标签的应急快照。恢复普通草稿时只合并实际编辑字段，避免初始化覆盖输入。
- 主模块不可用时仍可填写正文并下载草稿；加载恢复后接续已输入内容。
- 旧误提交 query 仅在没有较新应急快照时用于恢复。独立恢复全量复制快照，归档原稿失败则禁止切换覆盖；成功保存后移除地址中的文稿字段。
- 不清除浏览器数据，不强制刷新用户页面，不操作用户鼠标键盘。

## 验证入口

`scripts/test-writer-startup.mjs` 在 Chrome、Firefox、WebKit 每个引擎检查 11 个场景：立即输入、回车、主模块延迟、主模块缺失、预览模块缺失、存储恢复延迟、旧 query 恢复、较新应急数据优先、跨文档完整恢复、恢复归档失败保护、禁用 JavaScript 时不发生破坏性提交。

`scripts/test-writer-update.mjs` 使用 Git 中的 2838a7e 构造旧页面缓存，在独立 Chrome 中验证强制刷新取得新页面，同时保留已有测试草稿；没有操作用户浏览器。

```powershell
./scripts/build-web.ps1 -Output build/qa/startup-web
./scripts/build-web.ps1 -Output build/qa/returning-web
$env:PLAYWRIGHT_BROWSERS_PATH="$PWD/tmp/playwright-browsers"
node scripts/test-writer-startup.mjs
node scripts/test-writer-update.mjs
```

最终结果见本会话 [2026-10-21 日志](memory/logs/2026-10-21-01a158b0-startup-loss.md)。原始复现及测试文件位于被忽略的 `build/qa/startup/`，全部使用合成数据，不包含用户截图原文。

## 更新与恢复边界

旧页面若仍有未保存文字，应先复制保留，再在 Chrome 用 Ctrl+Shift+R 载入修复版；不要清理站点数据。浏览器中的既有草稿仍使用原地址与原存储键。

没有确认用户先前已经清空的内容已找回。浏览器历史读取未获授权，已停止且未绕过；仅有仍在表单、应急快照或旧地址里的字段时，修复后的代码才有可恢复来源。

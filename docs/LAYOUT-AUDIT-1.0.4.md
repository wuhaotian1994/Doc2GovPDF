## 实际发现与修复

- 备用可变字体默认字重为 200，导致红头和标题过细。固定为 400 正文、900 标题两种静态字重；新建 Word 嵌入 OFL 字体并声明实际字体名称，PDF 使用对应字体。
- 按字体轮廓校正红头的实际着墨上边界；修正信函首面双线、170 mm 线宽和下边线位置。正文文号与红色分隔线单独定位。
- Word 与 PDF 共用新建标题断行，避免把常见词拆开；正确区分章标题、条号和正文的字体。纪要姓名整体换行，不拆开“钱十一”等姓名。
- 尊重上游自动编号的 `lvlRestart=0`，修复换章后条号重复从第一条开始的问题。独立核对第一至第十四条各出现一次。
- 修复 Word 表格宽度收缩；保留导入表格的指定总宽、对齐和单元格垂直对齐。PDF 跨页重复表头，续页末闭合三线表，不丢行、不重复数据行。
- PDF 补齐新建文档的孤行控制，三行段落不会只剩一行在另一页。标题与后文、署名与日期保持相邻；短文落款带上前文，不再独占一页。
- 修复自动换页后的多余段前空白、页码两侧空格、附件说明悬挂缩进、附件标题位置、版记印发日期右对齐。
- 旧草稿重新读取源编号和版式元数据，保留用户正文；表格按稳定段落 ID 匹配，新增段落后不会套用错误的表格格式。

最终复查：所有页面内容可辨，无纸张外文字，无遮挡、缺页或附件错序；七类新建长文的数据行均完整保留，两个附件分别独立起页。通知/报告/请示的短样稿首面正文与落款已占据可用高度，第二页仅承载底部版记，与 Word 输出一致，这不是空白页遗漏。

96 dpi 图像测量的红头着墨上沿：普通红头 Go 71.97 mm、Word 72.23 mm（目标 37 + 35 mm）；信函 Go 29.90 mm、Word 30.16 mm（目标 30 mm）。红色分隔线宽约 156 mm，信函横线宽约 170 mm。离散像素及抗锯齿造成约 0.3 mm 测量分辨率，不能据此宣称印刷计量认证。

## 字体及兼容边界

本机未安装授权的方正小标宋。验证中的新建标题和红头实际使用 **Noto Serif SC Black**，不是方正小标宋；正文使用本机可用的仿宋等字体。备用字体随新建 Word 嵌入，系统字体不随安装包分发。严格要求指定字体时仍需安装单位授权字体并重启软件。

上游原样 Word 保留自身字体声明，当前 Word 因缺失原字体会替换其标题；原始参考 PDF 则已有原字形。Go 使用明示的备用字形。因此上游个别行宽、换行点和纵向位置存在差异，不能声称与原始 PDF 像素一致。新建 Word 与 Go PDF 的页数及结构已相互核对。Word 为验收导出的 PDF 对部分嵌入字形进行了栅格化；交付的 DOCX 文字仍可编辑，产品 Go PDF 的文字可提取。

没有在本轮运行 WPS、其他 Word 版本、打印机实打或 Windows 10。机检覆盖已实现规则，不构成完整国标认证，也不判断正文事实。

## 复现与证据

`scripts/test-layout.ps1 -Python <python.exe>` 会生成所有样稿，用隐藏 Word 渲染，运行 Poppler、pypdf 和 pdfplumber 核对。需要已安装 Word，Python 包 Pillow / pypdf / pdfplumber，以及 Poppler；可用 `POPPLER_BIN` 指定其目录。完成后必须继续逐页查看图像，脚本不会代替视觉验收。字体构建复现见 `assets/fonts/README.md`。

本地证据位于 `build/qa/layout-audit/final/`：`manifest.json`、`page-inventory.json`、`verification.json`、`measurements.json` 和 `rendered/`。每份 Word 渲染通过 `.word-source.sha256` 绑定实际 DOCX，防止拿旧图验新文件。回归包含 Go 测试与 vet、17 项隐藏桌面检查、34 条跨重启完整流程，以及 25 份真实界面导出文件的独立内容核对；全部通过。安装包验收结果另记在 `STATUS.md`。

排版实现参照本地上游源码及 [GB/T 9704—2012 政府网站刊载内容](https://www.ankang.gov.cn/WapContent-2060365.html)。字体嵌入和相邻段落行为参照 [Microsoft Open XML 字体嵌入说明](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.embedregularfont) 与 [KeepNext 定义](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.keepnext)。

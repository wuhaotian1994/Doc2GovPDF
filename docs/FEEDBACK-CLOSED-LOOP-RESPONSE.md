# 主动反馈：本地闭环交付与运营边界

2026-10-22，01a15c4c。回应[完整反馈方案](FEEDBACK-PRODUCT.md)，继续同PR #5。接收/回执、证据副本和处理界面的本地闭环已实际贯通；**真实收集尚未启用**，未将本机虚构任务等同公网或实际运营完成。

## 工作人员现在如何完成任务

正常填写页底部有稳定“反馈使用问题”入口。点击后才按需加载反馈模块并读同源接收配置；正常写作、保存、预览和导出不依赖反馈模块或接收服务。主问题是正在做什么工作、希望得到什么、卡在哪里；岗位/影响/联系方式/非文稿技术信息均可选，不要求注册、单位实名或公文。

准备时不预上传。截图可在本地裁剪、圈注、实际像素遮盖并生成不透明PNG，逐份看最终文件，可移除或回改。只有明确点击“从当前稿创建反馈副本”才读取最少可见结构，默认全不选；选定段落/表格后可逐格改值或替换身份数据。白名单保留段落角色、对齐、缩进、段前后及表头，拒绝原件/字体/作者/修订/批注/归档等隐藏属性。结构示例不是原始Word/PDF页码像素复刻，分页与字体关系可另附截图；原有Word无法可靠抽取时明确拒绝原件/恢复包，提供截图路径。

发送前集中显示本次文字、实际副本名称/大小/预览、可选联系/技术信息及接收主体/用途/访问范围/保留/删除告知，按钮明确发送范围。仅用户最终点击才发送。网络结果未知保留同一随机请求和凭据，重试不会重复创建；服务器确认后才给私密回执。若发送已确认而读取状态失败，仍可保存回执、只重试读取，不再发送一次。

私密回执可下载、手动恢复后查询状态/补充/读回复/删除单附件或整条。凭据只在Authorization头发送，不进入URL或浏览器长期存储；回执文件需用户自行保存，关闭标签页前应保留。未确认发送保留在当前标签页，不承诺跨关页找回；不偷偷持久化公文或凭据。

处理侧`feedback-admin.html`由显式私密凭据开启，可读岗位目标、指派负责人、回复、变更状态、关联修复版本/同类问题、删除。切换条目立刻撤下旧编辑表单，迟到成功/失败响应不能覆盖当前选择；退出使旧响应失效。回复已接收但重读失败时，只重试读取并保留未保存处理字段。

## PostgreSQL与边界

`cmd/feedbackd`与`internal/feedback`负责接收和私有附件，正文写作仍全本地。真实PG保存条目、补充、处理和必要私密事件，随机访问凭据只存hash；附件每次鉴权，不靠公开URL保密。接收限请求/文件/像素/并发，PNG服务端再次白底重编码、去隐藏RGB/元数据，JSON严格白名单重编码。原DOCX/ZIP/PDF/任意恢复包拒绝。

删除已核对正文/回复/附件/事件四表及私有文件实际清理；删除请求的短期hash墓碑阻止不明重试重建内容。失败显示尚未确认，并重试待清理材料；不把界面隐藏当删除，不承诺磁盘/WAL或外部备份即时抹除。静态目录采用os.Root约束与真实路径检查，链接及两点目录名不能旁路附件鉴权。

## 验收事实

- 政务仅文字、学校选择表格副本、医院截图副本，均通过实际UI→真实PostgreSQL接收→处理回复/状态/版本→补充→单附件/整条删除。此项是独立UI harness经同源代理连接本机真实服务，另有正常writer入口实测，不冒称盲测。
- 正常writer入口12项：从真实编辑面创建虚构3×2表，主动选表后确认发送，PG取得原网格、表头和空白；未选正文不发送、当前稿不变；无接收器时发送禁用但继续写作和保存。
- 三浏览器功能/已接收后读取失败/迟到详情响应共138项，证据组件三浏览器51项；6份实际PNG/JSON经独立像素与JSON检查后，通过当前严格PG接口接收/私密读取/删除。192个遮盖像素、透明度、裁剪偏移、无隐藏原信息均核对；这不等于自动保证可见文字/像素已匿名。
- 入口隔离8项：反馈模块失败、旧HTML无入口都不能阻断写作；实际稿保存后可刷新重试。现有三浏览器启动保护33项仍通过。受影响Go包office/webengine/feedback/feedbackd/webserve全量test/vet通过；资源与证据Node21项通过（数量不与其他分组重复相加）。
- 同一用户39块三表原稿在最终整合writer正常恢复/save/reload/导出，反馈请求严格0；DOCX同已审0103c65e，PDF全部7页内容流和渲染像素同已审页。原稿、图片、私密回执与管理员凭据均未提交。

真实联调发现并修正：回复成功后状态读取失败无法保存回执、处理回复重复发送风险、切换条目旧表单可写/过期响应覆盖、连接错误被“未启用”覆盖。第一次独立测试服务因QA首页未生成而拒绝启动，是测试准备错误；已加资产与健康检查后重跑，没有把该失败归咎产品。证据摘要位于[evidence/feedback-closed-loop](evidence/feedback-closed-loop/)。

## 实际启用条件

当前一般静态网页未连接收集服务；反馈面板明确不可发送，正常写作保持可用。独立本机开发实例只接受本轮虚构验证用途。实际运营主体/处理人员范围、保留与外部备份清理、部署授权须落实后才可真实启用。当前没有通知sender，界面明确提示、服务拒绝notify:true；可凭回执主动查看回复，不以联系方式暗示已开通通知。若需要自动通知，渠道和实际发送仍是待落实项。

本轮交付本地A/B闭环和可检查的真实数据流，不宣称C运营关口完成、不自行合并PR。运行与API详见[服务README](../internal/feedback/README.md)；字体内存与415字崩溃边界见[单独回应](FONT-MEMORY-RECOVERY-RESPONSE.md)。

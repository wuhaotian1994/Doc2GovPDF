# 使用需求反馈：完整产品方案
状态：2026-10-22 用户最新纠正优先：反馈入口是一句白话、可选图片、可选联系方式，不是工作背景问卷。列为现有 P1 完整交付内的交互修正；PostgreSQL 不变。PR #5 已有反馈 UI 与本地闭环实施记录，以下新交互目标尚待实现及独立复验，真实收集与运营关口仍未完成，不授权公开部署。

## 出发点
用户要求方便表达“想如何使用”，且必须明确服务器上传与脱敏；随后明确否定先按开发省事裁成“最小方案”。适合本产品的方案应覆盖表达、证据准备、确认发送、回执补充、处理回复和删除，而不是只有一个留言框。简单体现在用户不费力，深度体现在真实岗位问题能够说清并被处理。

正常写作、预览、导出继续本地处理。反馈是独立、由用户明确开启的数据发送通道；不把建设反馈服务解释为所有文稿上云。

## 1. 一句话就能提真实需求
- 当前工作区有稳定反馈入口，就地打开，不丢稿、不要求先退出任务。
- 默认只呈现一个自然表达框，例如“想怎么用，或者哪里不好用？”，一个“截图说明”入口、选填联系方式与发送动作。用户用一句白话即可完成，不要求分类、注册或填完整报告。
- 删除单独的“补充工作背景”以及岗位、目标、影响字段，即使折叠为选填也不保留这套问卷。确需澄清时，处理人员在收到反馈后针对缺口追问，不把后台整理工作交给用户。
- 图片也不必有；可截图、粘贴或拖入图片。结构化示例副本能力保留在按需补充材料处，不与一句话反馈并列成必经准备流程。
- 本次发送可正常附带有助定位的非文稿信息：应用版本、浏览器/系统版本及必要的已去内容化错误代码，使用明确字段白名单，并用一行“附带版本与运行信息”说明、可展开核对和关闭，不要求用户逐项研究技术字段或额外填表。非文稿信息不等于全部无风险：不默认带正文、标题、文件名、网址参数、操作轨迹、原始日志、令牌或设备唯一标识。

## 2. 截图从当前问题开始，不要求先存文件
- “截图说明”一次点击发起截取当前界面的流程；默认回到实际问题界面，不把反馈弹窗遮住的问题当作证据。用户框选所需区域，进入本地预览，可裁剪、圈注、像素遮盖、重截或移除；准备完成返回原反馈，已写文字保持。
- 如采用浏览器屏幕捕获，必须由用户主动触发并选择/授权捕获来源；先简短提示选择本页面，随后在本地框选。不得承诺所有浏览器都能省掉系统选择器，不绕过权限，不以长期录屏或音频采集代替单张截图。取得必要画面后停止捕获；取消、拒绝或失败回到原反馈，不反复请求授权、不上传。
- 粘贴/拖入图片自然可用；“选择图片文件”是兼容性或已有图片的补充途径，不是主路径。不支持屏幕捕获时就地说明并提供上述替代，不让用户先自己保存截图成为所有人的前置工作。
- 预览直接显示最终待发图片，遮盖写入最终像素而非可移除图层；原始捕获画面、未选区域和编辑历史不上传。常见路径不需要填写像素坐标、理解“生成副本”术语或反复确认加入清单；精细操作可按需提供。
- 只在内容可能暴露的位置给必要提醒，例如“图片会随反馈上传，请遮住不想发送的内容；不要上传涉密材料”。普通界面截图不先走合规问卷，也不被自动判为涉密。自动识别只是辅助提示，不声称全部脱敏。
- 复杂问题仍可按需提供示例文稿副本，选择必要内容、替换身份与业务数据并预览；正文、表格、批注、修订和文档属性等隐藏内容须有明确处理边界。不能可靠处理时保留原件且建议可检查示例或截图，不自动传原文件。
- 本地准备不云端预上传、不后台发送原稿；取消、失败或放弃不改写原稿，也不让原件进入重试队列。

## 3. 一处看清将发送什么，再发送
发送边界在当前反馈中清楚可见：已写文字、图片缩略预览（可打开检查/移除）、选填联系方式，以及简短的版本信息说明。用户看见的范围与实际请求一致，不能每次跳到另一页重复阅读原文、逐项勾选声明，或把一句话变成多步提交向导。

主操作旁简短说明“反馈及所选图片会上传到服务器，文稿不会自动附带”，并展示真实接收主体与可打开的用途、访问、保留期限及删除说明。涉及用户主动提供的文稿/图片时，在相应预览处提醒核对和遮盖。发送按钮明确表达发送行为；直到用户点击发送都不上传内容，补充材料也遵循同样边界。具体布局由实现方选择，不能为简洁隐藏真实数据范围。

普通非文稿运行信息无需被包装成敏感文稿；用户输入或截图中的私人/文稿内容也不能因“只是反馈”而默认安全。不承诺完全匿名；如必要基础设施记录 IP，应准确说明并限制用途/保留，不扩为追踪分析。正常写作仍本地处理，只有主动发送反馈是例外。

## 4. 提交不是终点
- 服务端确认可靠接收后，才显示成功与回执。失败保留本地填写；结果不明时允许核对状态，避免重复提交多条相同反馈。
- 反馈人可凭受保护的私密访问方式查看状态、补充说明/材料、阅读回复和申请删除；公开或连续编号本身不能成为读取他人内容的凭据。
- 联系方式可选，通知单独选择；通知只提示进展，不把私密文稿或描述塞进邮件内容。
- 状态应让用户明白：已收到、需要补充、正在处理、已有解决办法或暂不支持及原因。不能永远显示“已收到”，也不自动承诺处理时限。
- 删除支持误传附件的单独移除。正文、联系信息、附件、预览副本、未完成上传、备份都须有可执行的保留/清理规则；前台隐藏不等于已彻底删除。

## 5. 处理侧能理解并负责
内部处理入口从用户原话与图片理解需要，允许处理人员整理场景、指派负责人、针对性请求补充、关联同类问题、回复结果并关联修复版本。岗位、工作目标等是处理侧的理解维度，不是反馈人必填或单列的表单；不能只按报错代码统计而丢失使用意图。

原始反馈与附件默认私密。进入公开研发议题的内容必须另行整理和审查，不自动同步原文或附件到公开GitHub，不默认交给第三方AI或用于训练。不要把用户提交需求视为对任何后续用途的授权。

不扩建社交、积分、营销或社区平台；支持完整表达与处理，不意味着让每个用户使用所有能力。

## 6. 合适的服务构成
建议包含反馈前端、接收服务、反馈数据库、私有附件存储及内部处理后台：
- 接收服务负责输入验证、合理限流、提交去重、明确结果与访问鉴权。
- **数据库使用 PostgreSQL（2026-10-22 用户明确指定）**，保存需求、状态、回复、处理关联、附件关系和必要审计信息；大附件与衍生预览存入私有文件/对象存储，不靠公开URL保密。
- 附件逐请求鉴权，限制类型、真实格式、大小、数量及解压资源；先隔离检查，再允许处理人员读取。解析和预览必须受限，不能信任客户端扩展名、文件名或脱敏声明。
- 日志记录接收、访问和删除等必要事件，不默认记录反馈正文、附件内容或访问凭据。权限与备份清除也属于交付的一部分。
- 正常写作不依赖反馈服务健康；反馈不可用不得拖死编辑、预览或导出。

这些能力是完整方案的一部分，但不强制独立微服务、自建数据库服务器或某家云厂商。实施方应依据实际部署条件选择，并明确数据流；此文没有配置账号、凭据、数据库或公网服务的授权。

## 7. 上线前必须解决的运营条件
接收运营主体、反馈处理负责人、访问人员范围、正文与附件保留期限、备份清除时限、删除与联系途径必须实际确定并展示。不得用尚未落实的政策占位文案冒充已执行。也不能因暂未配置服务就把失败伪装为成功。

## 8. 完整交付验收
0. 首次用户输入“这个表格不好改”，不填背景、岗位、目标或影响，不留联系方式即可发送并取得回执；截图任务从当前界面一键发起、选择必要区域并预览，不先保存图片文件，取消/拒绝捕获后文字和当前稿仍在。粘贴图片、兼容回退和键盘操作同样可达。版本信息紧凑可见且可关闭，实际请求不带文稿或原始日志。以下复杂材料能力按需使用，不能成为这条常见路径的前置步骤。
1. 学校办公室用公开/虚构回执说明现成表格难整理：可保留结构制作副本、确认发送、获得回执、补充、得到处理结果。
2. 医院行政人员用虚构数据截图说明排版问题：可裁剪遮盖，最终上传文件中被遮盖信息不可通过移除图层恢复，原稿不受影响。
3. 政务经办仅描述工作目标：不必提供单位实名、联系方式或公文，仍可反馈并查询回复。
4. 确认未选中的当前稿、原附件和隐藏内容没有出现在发送请求、日志或公开议题；取消与发送失败不改变原稿。
5. 错误类型、超大/恶意附件、重复/结果不明请求、权限越界和删除路径均有可验证结果，不以“弹出脱敏提示”代替安全能力。
6. 涉密材料和无法确认处理范围的输入不会因自动检查或勾选提示而被暗中放行。自动提示不是法律合规或零泄漏保证。

### 关口 A：先接通一条可追踪的本地闭环
同一工作区用一句自然表达、可选图片与联系方式反馈，不单列岗位/目标/障碍问卷；明确发送范围与服务器提示；接收服务写入 PostgreSQL，可靠接收才返回回执。受保护的回执可查询、补充与读取处理回复；处理侧能接手、变更状态并关联修复版本。先用明确虚构文字验证成功、失败保留、结果不明核对及重复提交去重。正常写作、预览、导出不依赖反馈服务。此关口不是以“只有留言框”结项。

### 关口 B：把真实问题证据与隐私保护一起交付
接通可选截图/结构化示例副本、本地脱敏与最终预览、准确发送清单、私有附件和逐请求鉴权；覆盖隐藏信息边界、隔离检查、误传附件移除、整条反馈删除及保留/备份清理。未选择的当前稿、原件、未经主动操作的截图和内容日志不得随反馈上传；用户主动截取并核对的最终图片可以发送。数据库与文件删除结果必须能核验，不能只删界面记录。按第 8 节学校办公室、医院行政及仅文字政务经办任务走完表达到回复/删除，不用开发测试数量代替岗位体验。

### 关口 C：明确运营后才允许启用收集
在实际接收用户材料前落实第 7 节的运营主体、处理负责人、访问范围与保留/删除规则，检查页面告知与真实部署一致；给出版本、端到端证据及未完成项，再申请所需上线授权。运营信息未确定不阻止用虚构材料完成本地开发和验证，但不能先收集真实材料再补政策。本方案不授权 CEO 创建数据库、账号、凭据或对外服务，不授权公开部署。

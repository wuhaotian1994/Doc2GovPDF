# Doc2GovPDF 产品需求

版本：0.3。日期：2026-10-14。状态：本地版 1.0.0 交付基线。本文件保留产品目标，实测范围以 [验收记录](STATUS.md) 为准。

本轮发布决定：用户明确要求“暂不公开，先保留本地版本”。因此本次交付本地 EXE 安装包，不创建公开仓库、不上传内容、不启用联网更新。更新机制继续保留并内部测试；公开托管、生产发布密钥、代码签名以及干净系统/Windows 10/真实用户验收留待公开发布阶段，不能声称已完成。

Slogan：让小白用户能最简单的步骤完成公文生成与机检。

## 产品目标

将已写好的内容转为版式规范、问题可核对、能够交付的公文。用户只需要导入文件或填写内容、确认必要问题、导出成品。软件负责排版、规则检查和文件生成。

用户明确要求：以 Go 重写 gongwen-kit 核心能力，设计图形界面，以可直接安装的 EXE 安装包交付，支持后台自动静默更新。后续开发由本项目持续推进，常规技术选择不要求用户参与。

首版默认方案：简体中文、Windows 10/11 x64、本地单用户使用，无需登录，DOCX 为可编辑成品，PDF 为固定版式成品。Windows 10 属于兼容性目标，具体可支持的系统版本及运行组件在技术验证中确定。

本产品的“生成”首先指用用户提供的内容生成公文文件。自动撰写事实、联网 AI 写作和内容真实性判断不在首版范围。

## 目标用户与主要任务

| 用户 | 主要任务 | 当前障碍 | 产品响应 |
| --- | --- | --- | --- |
| 不熟悉排版的办公室人员 | 把现有正文整理为公文 | 字体、编号、页码反复调整 | 导入后自动排版，必要信息就地补齐 |
| 经常出稿的文秘人员 | 沿用单位格式并检查 | 重复填单位信息、人工核对数字 | 单位预设、问题定位、修改复用 |
| 复核人员 | 确认改动与未解决问题 | 自动修改不透明、问题难对应原文 | 修订留痕、检查范围与问题清单 |

## 体验方向

以 [Squoosh](https://squoosh.app/) 的文件处理流程为参考，以 [ImageOptim](https://imageoptim.com/mac) 的专注程度约束桌面形态，采用 Windows 熟悉的窗口、文件选择与键盘操作。文件进入后，工作重心立即转到结果预览和必要调整，最后保存。具体映射与约束见 [交互参考](UX-REFERENCE.md)。

主流程是“交入内容 → 查看处理结果 → 导出”。这是三个任务阶段，不承诺所有文件只点三次；无问题的文件不增加确认步骤，有问题的文件才进入相应处理。

首页主入口为导入 DOCX 或粘贴正文，辅助入口为从模板新建。接收内容后自动解析、检查，在工作页展示预览与问题；原文、修改结果与问题可以关联定位。文种、单位预设和成品格式使用合理默认值，专业参数按需展开。

## 首版功能范围

P0 是首次正式交付必须满足的范围；P1 在核心流程验证后扩展。

| 编号 | 优先级 | 能力 | 验收要求 |
| --- | --- | --- | --- |
| IN-01 | P0 | 导入 DOCX、粘贴纯文本 | 拖入与文件选择均可用；自动进入处理；原件不修改 |
| IN-02 | P0 | 从模板新建 | 提供通知、报告、请示、函、纪要、管理办法及非红头文书入口；示例内容清楚标记，不能误当用户正文 |
| ED-01 | P0 | 必要内容编辑 | 可修改正文和标题结构，补充发文机关、日期等要素，编辑简单表格；不做完整 Word 功能集合 |
| ED-02 | P0 | 单位预设与草稿 | 常用机关名称、发文字号前缀和输出偏好可保存；草稿自动保存、可恢复 |
| LY-01 | P0 | 生成与排版 | 按模板处理页面、标题、层次、编号、页码、落款、附件及版记；特殊体式使用独立模板 |
| CK-01 | P0 | 格式与体例检查 | 对可读取的页面、字体声明、编号、日期、发文字号等给出位置、解释和依据 |
| CK-02 | P0 | 数字检查 | 支持明确结构的合计、占比与列举数量检查；跨处指标比较在证据不足时仅提示 |
| CK-03 | P0 | 文风与用字检查 | 可确定的规范项与风格建议分级；引用、网址、专有名称等有保护或人工确认机制 |
| FX-01 | P0 | 可控修复 | 格式修复可撤销；文字修改逐项或按同类确认；数字不自动改；保留修订和已有批注 |

| DS-01 | P0 | 安装与更新 | 双击 EXE 安装即可使用；支持后台检查、下载、安全替换和失败恢复 |

首版导入保障范围是正文段落、常见标题、简单表格及常见公文要素。复杂浮动对象、嵌套表格、公式、宏、加密文件和复杂既有修订先检测再处理：无法保证保留时进入只检查模式或明确拒绝，不能静默丢弃。

旧版 DOC、扫描 PDF、OCR、OFD、电子签章、审批流、协同编辑、移动端和云端存储不纳入首版。PDF 首版作为输出和版面核验对象，不承诺可逆编辑任意 PDF。

## 检查与修改规则

检查结果分成“需修正”“需核对”“建议”和“未检查”。每条问题包括原文位置、触发原因、建议动作与适用范围；条款依据可以展开。推断出的结构和指标必须说明不确定性。

格式、文字和数字采用不同操作权限。对已识别且受支持的结构可批量修复格式；文字修订必须可查看和拒绝；金额、数量、日期含义和指标口径不能由系统猜测。遇到原有修订时保留作者和状态，不能替用户接受或拒绝他人的改动。

接受、拒绝、忽略和手工修改都记录在当前文档的本地操作记录里。忽略只作用于本次文档或当前版本，不自动关闭全局规则。文件内容改变后原检查结果标为过期，重新检查后才能导出带最新结论的成品。

检查通过的表述为“在已检查范围内未发现问题”，同时列出未检查项。未渲染的 DOCX 不能声称通过 PDF 字体和分页核验。格式符合性、内容真实性和单位内部审核分别呈现，不能由机检生成“完全合规”结论。

“需修正”项未解决时仍可保存草稿和原件；正式导出默认要求处理这些项。用户可选择导出待核对副本，应用中的问题状态继续保留，不显示检查通过。建议项不阻断导出。

## 文件输出与 PDF

默认名称带“规范稿”或“修订稿”后缀，重名时自动递增；写入前检查目标位置是否可用。DOCX 与 PDF 使用同一个冻结的内容版本；导出期间继续编辑不得混入本次成品。

PDF 是正式首版的必备能力。目标是在未安装 Word/WPS 的设备上完成核心流程，所需本地组件由安装包管理。渲染方案在第一阶段验证；未经验证不能将该目标宣称为已实现。

PDF 预览与导出必须采用同一渲染结果。DOCX 在第三方编辑器中可能重新分页，因此需要记录经过验证的 Word/WPS 版本和支持范围。渲染失败时保留可用 DOCX 和草稿，提供具体重试动作，不能输出空白 PDF 冒充成功。

首次使用和导出前检测必要字体，缺失时给出可执行的补救提示。可以生成明确标记的替代字体预览，但不能将替代结果标成字体检查通过。安装包只能携带具备分发授权的字体和渲染组件。

## 安装与静默更新

交付物为版本化的 Windows EXE 安装包，并支持桌面启动、升级和卸载。用户无需配置命令行或自行安装开发环境。优先采用当前用户安装；受单位策略限制时提供管理员部署路径和离线安装方式。

自动更新默认开启，首次安装说明联网用途，在设置中可关闭或改为手动。应用运行时启动检查，此后最多每 24 小时自动检查一次；后台下载，应用退出并结束文档任务后完成替换，下次启动进入新版本。不强制重启系统或终止编辑，不要求永久驻留服务。

更新必须校验可信签名、版本及文件完整性，使用安全传输；校验失败继续保留现有版本。采用原子替换与旧版本保留，启动失败可回退；数据迁移先备份并具有兼容或恢复方案。离线和更新服务不可用不影响出稿，失败不能反复弹窗。

发布渠道、托管地址和代码签名证书在发布阶段落地。这些是公开交付依赖，需求阶段不预设已有账号、证书或服务。

## 本地数据与异常处理

正文、草稿、预览及检查均在本机处理，不因更新功能上传文档。默认无使用统计，日志不记录正文；诊断信息导出由用户主动触发。设置提供本地数据位置、清理记录和关闭最近文件的选项。

安装卸载不得默认删除用户成品；清除草稿和设置需独立选择。导入外部文件时限制解压后大小和对象数量，不执行宏、不自动访问外部链接。临时文件随任务清理，异常退出后的残留在下次启动处理。

错误提示必须提供下一步。例如文件被占用时建议另存或关闭占用程序，结构不支持时说明受影响内容，磁盘不足时保留草稿并允许换位置。所有耗时任务显示阶段，可取消，取消不得破坏原件。

## 验收与性能目标

以下是待实测的首版目标，不是已完成指标。性能基准机采用 Windows 11、4 核 CPU、8 GB 内存、SSD；另在 Windows 10 兼容环境验证。测试样本与机器配置随结果归档。

| 维度 | 交付门槛 |
| --- | --- |
| 首次使用 | 至少 5 名非技术测试者中 4 名无需指导，在已有正文、无需人工处理问题的场景下 3 分钟内完成导出 |
| 安装 | 干净虚拟机未装开发工具及 Office，可从完整离线安装包安装并完成受支持样稿的 DOCX/PDF 输出 |
| 启动与反馈 | 冷启动目标不超过 3 秒，长任务开始后 1 秒内可见阶段反馈 |
| 常规文件 | 20 页以内、20 个简单表格、10 MB 以内样稿，结构机检目标不超过 5 秒，PDF 导出目标不超过 15 秒；首轮实测后定版 |
| 文件上限 | 首版目标支持 100 页或 50 MB 以内的受支持文件；超限提前提示，不能卡死或静默截断 |
| 内容保真 | 原文件摘要不变；拒绝本软件全部文字修订后正文与原稿一致；受支持的既有批注、链接和对象不丢失 |
| 规则质量 | 每条阻断规则有必错、必过与边界样例；模糊规则不得充当确定错误；迁移差异有明确记录 |
| 版面质量 | 每种首版模板至少有短文、跨页、附件或表格适用样例，检查 DOCX 结构并逐页核验实际 PDF |
| 恢复 | 运行中崩溃后可恢复最近一次自动保存草稿，自动保存间隔目标不超过 5 秒 |
| 更新 | 覆盖断网、包损坏、签名错误、文件占用、编辑中下载、升级后启动失败与数据回退测试 |
| 可访问性 | 1366×768 显示及 100%/150%/200% 缩放下主操作可达，键盘可以完成导入、问题导航和导出 |

安装包体积与空闲内存必须在渲染方案验证时实测，再冻结发布预算；不为追求小安装包把必需组件的手动安装转嫁给用户。

| 2 最小可用流程 | DOCX/正文输入、常见模板、基础检查、预览、DOCX/PDF 导出 | 普通用户能独立完成一次常规出稿 |
| 3 首版完整能力 | 数字与文风规则、修订、问题定位、草稿恢复、特殊模板 | P0 功能与支持范围内的回归用例通过 |

产品、设计、编码、测试与本地提交由项目负责人自主推进，不将常规选择交给用户。只有无法从现有授权解决的外部账号、付费、不可逆发布或关键业务口径才请求决定。使用 Impeccable 固化产品与设计上下文，并在 UI 变更后进行审查。

用户不承担半成品测试：P0 主流程、文档兼容性、PDF、安装及更新等必要能力完成并经过内部验收前，不主动发送预览程序、截图或请求试用。检查报告不作为面向用户的功能，软件必须直接帮助用户把文件处理好。

## 2026-10-18：改为纯网页版

用户明确改变交付形态并否定旧桌面 UI。当前主目标改为静态网页版：Go/Wasm 在浏览器本地运行，文件不上传，草稿使用 IndexedDB，下载 Word/PDF，缓存就绪后可离线使用。EXE 安装与后台安装更新不再是当前版本交付要求；网页资产在重新打开时更新。之前“暂不公开”继续有效。新视觉系统与验证记录见 DESIGN.md 和 WEB-2.0.md，旧版本记录作为历史保留。

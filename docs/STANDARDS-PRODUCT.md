# 全文国标优先：产品与验收约束
状态：2026-10-22 用户最新方向，尚不代表现有实现全面满足。当前实施/证据/未核范围见[内部覆盖合同](STANDARDS-COVERAGE.md)。

## 第一原则
用户明确要求：“国标才是第一准则”“不止字体，国标应该贯穿全文”。因此适用国标应贯穿内容要素、排版生成、预览、实际Word/PDF、检查与交付状态，而不是只做字体选择或增加若干提示。“深者不觉其浅，浅者不觉其深”是使用方式：标准复杂性由产品承担，不以易用或实现方便降低出品要求，也不把全文条款甩给使用者。

## 标准范围与准确性
[国家标准平台](https://std.samr.gov.cn/gb/search/gbDetailed?id=lOIe27f77QU%3D&mode=p)确认GB/T 9704—2012《党政机关公文格式》现行，2025-05-30复审继续有效。[条例官方转载](https://www.mem.gov.cn/xw/ztzl/2018/cyzd/lxyz/201207/t20120708_228323.shtml)与[高校党政办公室标准全文](https://dzb.cumtb.edu.cn/info/1040/1184.htm)可核对适用范围和条款。

不能把标准分类中的推荐性，偷换成党政公文格式可任意处理；也不能无视适用条件，把所有可选要素都要求用户填写。须分别保留强制用语、一般要求和条件适用条款的区别。标准引用的数字、标点、量和单位等文件，应核对适用版本；普通编辑润色不冒充国标要求。其他单位的参照使用、特定格式及电子公文归档/签章另有边界，不能因生成了PDF便宣称全套认证。

## P0：建立全文的标准合同和真实出品状态
内部维护可追溯的规则覆盖记录：条款与版本、适用条件、所需事实、生成约束、检查方式、实际证据、未检查边界。它是实现和验收依据，不是要求另建一页报告让用户阅读。

至少覆盖这些相互关联的部分：
- 全文纸幅、版心、边距、文字颜色、字体字号、行字安排与分页；
- 有条件适用的版头要素与各自位置；
- 标题、主送、正文层次、附件说明、署名、成文日期、附注及签章相关版式条件；
- 附件名称/序号与实际内容对应，表格横向方向、跨页和页码连续关系；
- 版记、抄送、印发信息、分隔线、页码及例外；
- 特定公文格式，以及标准涉及的文字、数字、标点和计量规范。

纸张物理性能、真实双面印制、油墨、印章真伪及装订等不能靠屏幕渲染认证，应明确相应交付/人工核对边界。不能将未支持或未检查显示为已符合。

面向用户的状态要区分：本次已核符合、存在不符合、需要事实核对、不适用、未检查/不支持。允许继续草拟不等于通过最终标准检查；“保留原样”记录用户选择，不将不符合洗成符合。

不得为了凑齐要素造事实：发文机关、成文日期不当然等于印发机关和印发日期；文号、签发人、密级、印章和附件实际存在与否均不能猜补。当前构造存在复用agency/date为印发信息的静态线索，应核实实际适用与输出，不在未复现前宣称所有稿件都错。

## P0：本机符合要求的字体优先真实使用
现有“默认开源备用、单位指定再手选”的产品取舍被本条替代。不能让替代字体成为规范默认，也不能把Noto等备用字族等同于小标宋、仿宋、楷体或黑体。标准规定的类别不等于某厂商品牌是唯一实现。

期望完整路径：
1. 用户可理解地选择使用本机公文字体。支持时由用户主动触发浏览器授权，本地处理、不上传字体；不要求已安装字体的人先找系统文件。
2. 显示真实字体名称、字体面、角色用途与缺失项，不能仅因把任意文件登记为“仿宋”就认定符合。字体集合应正确选择所需字体面，字符覆盖及回退有明确结果。
3. 浏览器不支持、权限未给、读取失败和确实缺失分别说明；提供用户可完成的本机文件选择途径，不把无读取权限误报为未安装。
4. 尊重实际使用/嵌入许可；技术标志不等于法律授权证明。原件和字体配置保持，遇缺字/不可用不静默换备用后仍宣称标准成品。
5. 备用可用于明确的草拟或预览降级，但状态不能误导。字体是全文标准的一部分，不是获得一个绿色字体标记就算整稿合规。

[MDN Local Font Access](https://developer.mozilla.org/en-US/docs/Web/API/Window/queryLocalFonts)及[Chrome官方说明](https://developer.chrome.com/docs/capabilities/web-apis/local-fonts)说明浏览器支持、用户交互与权限限制。CSS能显示本机字体不等于PDF引擎已取得真实字节。限制应转化为清楚可完成的产品路径，不是降低标准的借口。

## P0：预览与导出必须使用真实证据
- 绑定同一稿、同一配置、同一版本，核对真实PDF使用/嵌入的字体、缺字与回退、页面结构，而不只检查选择框或角色字段。
- Word分别说明已嵌入并验证，还是依赖接收端具备指定真实字体；选过字体不能保证跨机器同样显示。预览PDF好看不能替代Word实际验证。
- 字体的预览打印、可编辑嵌入等用途须区分；[OpenType fsType](https://learn.microsoft.com/en-us/typography/opentype/spec/os2#fstype)是技术依据，不代替许可核实。
- 引擎发出的降级警告必须在用户相关路径真实可见；不能以内部已有warnings字段宣称完成告知。
- 当前源码静态核对发现自定义字体注册角色与实际身份、TTC首个字体面、PDF缺字回退、DOCX仅嵌入备用字体等边界，应逐项验证修正；这是待落实产品风险，不是已完成客户环境验收。

## 统一工作区中的原件与规范化
原件保护、原样转存与按规范整理不是同一个结果，但不能因此拆回两套普通/advanced产品。一个工作区清楚说明本次在做什么、哪些能力/要素受影响，保留原件及撤销能力。
- 原样保留不表示已规范化；不让一次保留确认变成“全文符合”。
- 规范化不得静默删表、压平结构、改变事实或伪造签章。
- 导入暂不支持的结构须明确影响和可行交付，不能仅以文字还在认定保真。
- 前台优先给具体结果与可行动判断，详细依据按需查；不把国标第一实现为几十段重复说明或一个总“全部采纳”。

## P1：以真实岗位与文件验收
用从空白起草、原生Word接收、联合/附件/横表等适用任务验证完整链路。覆盖正确本机字体、权限未给、字体缺失/缺字、恢复草稿和实际导出；核查相关文件而非只数测试通过项。
针对实际规则差异，在需要时用工作人员能回答的业务问题确认，不逼用户先学习标准条款，也不暗猜。完整覆盖状态和未检边界必须随证据维护；本文件不是公开上线、签章或合规认证授权。

CEO只提出原则、问题、优先级和期望结果，具体实现由工作Agent选择。本方案未安装字体、读取客户电脑、创建服务、合并PR或公开部署。

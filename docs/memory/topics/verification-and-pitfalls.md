整理日期：2026-10-20。条目指向证据，不代替最新代码复验。

## 文档引擎

| 经验 | 曾经发生的情况 | 下次如何避免 / 证据 |
| --- | --- | --- |
| 必须用真实 Word 打开修订文档 | XML 看起来正确、测试通过，Word 仍报损坏；删除节点脱离命名空间后改名失败，新插入节点又复制了旧格式修订 ID | 删除文字正确写为 `delText`，跨正文/页眉页脚分配唯一修订 ID；真实只读打开验收。见 [1.1.0 记录](../../LAYOUT-AUDIT-1.1.0.md)、日志 E04 |
| 中文 PDF 必须用负例验证 | PDF 解析库错误处理多字节 CMap 和 CID 字宽，字体负例才暴露问题 | 保留 `third_party/pdfreader/DOC2GOVPDF-PATCHES.md` 补丁和 CJK 回归；不要直接换回未修补依赖 |
| 自动通过不等于版式通过 | 曾遗漏红头入口、分页、签发人对齐、附件说明连页等问题 | 对实际 Word/PDF 逐页看图；按产物摘要关联已审阅图片，见两版 LAYOUT-AUDIT |
| 不改原件来追求截图一致 | 上游 PDF 和公开 DOCX 并非同次导出，本机又可能缺少商业字体 | 区分字体回退、源格式与生成缺陷；未编辑 DOCX 要按原字节输出 |

## 浏览器与存储

以下恢复能力仍在当前移植分支的未提交工作中，不能据此假定已交付，详见 [交接](../handoffs/01a13839-web-port.md)。

| 经验 | 原因 / 结果 | 验证或下一步 |
| --- | --- | --- |
| IndexedDB 多键写入抛异常要显式 abort | 在第二次 `put` 抛错时，仅让 Promise reject 可能让第一次写入提交 | `BrowserStorage.write` 已改为异常时 `tx.abort()`；真实浏览器注入第二键配额异常，验证旧草稿字节不变 |
| 取消 Worker 必须终结启动等待 | 只 terminate Worker 会留下 boot Promise，使后续任务排队不再运行 | `EngineClient` 同时结束 boot 和活动请求；保留无关排队检查，重新载入字体。6 项 Node 故障测试已通过 |
| 草稿要校验、留旧副本，未知版本不得静默覆盖 | 单纯读取 JSON 后直接当作工作状态，会漏掉损坏和前向版本风险 | 包装记录含摘要；坏数据保留/回退；高版本阻止写入；显式恢复前归档当前数据 |
| 字体加载成功不代表保存成功 | 先更新 Worker 再写数据库，存储失败会导致当前预览与下次启动不一致 | 先只校验字体，存储成功后重启 Worker 应用；坏缓存字体使用明示回退 |
| 旧桌面草稿不能只恢复文字 | 导入的 DOCX 修订需要匹配原件，附件/表单/表格草稿也要保留 | `.gongwen` 包含原始 Word；旧 workspace.json 按 SourceID 关联原稿，错原件拒绝 |

## 测试与环境

- 后台运行：独立无头 Edge、隔离 profile、隐藏 Word。严禁为了验收使用用户鼠标键盘或前台 Office。
- CDP `Runtime.evaluate` 的异步代码要放在 async 函数中；顶层 `await import` 曾使测试脚本报错，不是产品启动失败。
- `Page.reload` 返回不代表旧 JS 上下文已消失。曾读到旧 `appReady` 后马上访问新页面，误报“草稿未恢复”；使用旧文档标记确认新上下文就绪。
- 浏览器下载必须等待 `.crdownload` 消失，不能在下载未落盘时结束测试浏览器。
- Python 文本读取显式指定 UTF-8，Windows 默认 GBK 曾使证据 JSON 读取失败。
- 本地预览请求可能受沙箱/系统代理影响。曾出现代理 502，而宿主 `curl --noproxy '*'` 返回 200。先区分网络执行环境，不能直接断言服务已停。
- Go 缓存使用项目 `tmp/gomod` 和 `tmp/gocache`；大型测试在独立输出目录构建，避免改动用户正打开的 `dist/web/`。
- 原始证据位于被忽略的 `build/qa/`。交付时把关键结果、代码版本、未验证范围写入已提交文档；不要只留一个本机路径。

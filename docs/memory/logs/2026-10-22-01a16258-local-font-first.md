# 首次预览优先本机字体

日期：2026-10-22；会话：01a16258。

用户明确认为上轮无授权首份 PDF 11.86 秒仍过慢，要求优先使用授权本机字体。沿用提交/同 PR 交付与指定 ECS 部署授权；不增加付费带宽，不更换直接下载 PDF。

首次支持 Local Font Access 的浏览器、没有已保存字体/预览选择时，显眼提供“使用本机字体”与“使用备用字体预览”；先写内容仍自动保存，选择前不开始备用字库下载。用户点击才请求权限，集中确认五种用途，按真实系统名称提出建议；缺少小标宋时明确以黑体草拟，不声称取得标准字体。已保存的用途优先保持，后续直接复用字节，不重新询问权限。

批量读取只取选定字体面，校验实际 PostScript 身份、嵌入技术限制；同一真实字体面只读取一次。整批检查完成才注册/保存；失败保留旧配置。原 Word 的字体设置强制完成受保护存储，并在失败时回退内存配置，避免界面以为保存成功。字体/文稿不上传。拒绝、空列表或不支持时保留文件选择与备用字体路径。

离线安装延后到首份真实 PDF 完成，不与首预览争用带宽；去掉两份重复 PDF.js .mjs 别名的预取。Wasm/字体排版算法本轮没有修改。

初轮 12 项本机字体流程（合成权限/枚举、真实 OFL 字节）通过；现有资源 13、冷启动 6、三浏览器启动 33、Node 11 项通过。没有读取客户机器字体，未以合成授权冒认系统弹窗实测。对新低负担确认界面做了一次整合视觉修订并确认，保留既有设计。中途测试误在压缩构建完成前启动，遇到旧 HTML；已对完整构建重跑，不把该结果计入通过。

当前进入并发代码整合和最终实物/公网验收，提交不等于生产更新；最后版本与实测补到 ECS 交接。测试包括精简 OFL 字体功能路径，并计划使用两份各约 14.85 MB 的完整字体做测速，明确测试夹具与真实系统字体的边界。

## E04 · 用户再次反馈推翻交付结论：真实 HTTP 服务故障

- 用户要求从打开立即输入，实际操作下一步、返回、刷新、保存和导出；不能把降级提示当作正常可用。随后明确要求完成后提交并 push，仍不部署公开网站。
- 在现用 127.0.0.1:37842 只读检查，PDF.js 主模块及 worker 的 `.mjs` 响应是 `text/plain`，浏览器拒绝执行。旧浏览器测试使用自写 Node 静态服务，强制设置正确 MIME，掩盖 Windows Go 文件服务的实际问题。E03 中“交付可用”的判断范围过宽，已被实际用户反馈和同地址独立浏览器复现推翻。
- 所有填写验收脚本改为启动实际 Go `cmd/webserve`。修复 `.js/.mjs/.wasm` 显式 MIME，保持 nosniff；预览使用新的 `.js` 别名绕过旧错误类型缓存。
- 真实服务又复现保存后刷新 `net::ERR_FAILED`：Go 将 `/index.html` 重定向到 `/`，旧 SW 缓存了 redirected 响应。改为缓存规范根入口，并兼容重定向响应；旧缓存一次性激活修复，不强制刷新正在编辑的页面。
- 旧版本升级实测再发现同秒资源替换被 Last-Modified 误判 304。静态 HTTP 不再使用时间戳缓存，离线版本缓存归 SW 管理。新增 Go 用例覆盖宿主 MIME 污染和同秒更新。
- 首次流程已增加“主模块延迟期间保存、关闭标签页、新标签重开”，独立审查发现旧 sessionStorage 方案不能跨关页恢复。改为每页独立 localStorage 恢复记录，拿到主编辑锁后归档其他版本；仅在保存成功且原记录未变化时清理，避免覆盖其他标签。
- 六配置验证进行中；Firefox 离线第一次失败来自仍保留的测试网络拦截，去掉仅用于模拟慢加载的路由后同一流程完整通过。不把模拟拦截失败伪称产品修复。

# 邮件到微信公众号草稿部署记录

日期：2026-10-27（Asia/Shanghai）；会话：01a177ae。

## 授权与需求

用户要求在已有 n8n 中，把指定邮箱收到的 Markdown 邮件转为微信公众号草稿，提供了公众号接口凭据及允许的发件人。封面先选择固定，随后明确改为邮件提供，并支持正文配图。按最新需求交付 article.md 与 JPG/PNG 附件规范。所有真实账号、AppSecret、密码和访问令牌留在服务器受限配置，不进入仓库。

## 实现与重要取舍

- 官方接口凭据、素材列表和草稿数量接口调用成功。n8n 工作流负责 IMAP 监听、发件人与主题过滤、调用本机私有适配服务；新增文章仅调用 draft/add，没有公众号发布动作。
- 适配器为 `/opt/n8n-wechat-mail/bridge.py`，systemd n8n-wechat-mail.service，专用非登录用户、受限文件系统、256MB 内存上限、自动重启。监听 Docker 私有桥接地址的 8789，不开放公网；Bearer 密钥存入 n8n 加密 Header Auth 凭据。
- 微信配置在 `/etc/n8n-wechat-mail/config.json`（root:专用服务组、640）；去重状态在 `/var/lib/n8n-wechat-mail/ledger.sqlite`（目录700）。相同文章编号与内容不重复创建；编号冲突拒绝；微信新增结果不确定时停止重试，避免重复草稿。
- Markdown先转换、清洗再加内联样式。封面上传永久素材，正文图片上传微信图片接口并替换链接；不拉取外部图片URL，限制附件数量、大小、格式，先校验所有引用，缺图不建文章。
- 首轮阿里邮箱 FROM/SUBJECT 组合搜索报 BAD，n8n触发器运行时停用。Python只读复核：基础 UNSEEN、SINCE、UID 可用，FROM/SUBJECT 不可用。
- 自动审批拒绝“下载全部未读再过滤”，担心超范围读取。向用户说明后，用户明确回复“允许下载全部未读邮件”。才实际部署 UNSEEN 搜索，之后在 Code 与服务双重过滤。邮件保持未读，按 UID 进度处理；其他邮件可能在 n8n 执行记录中，但不送微信。From白名单不是密码学身份认证。

## 验证与修复

- 测试夹具初版缺列表闭合符，编译发现后修正。最终7个单测通过，覆盖错误发件人、缺图/坏图/重名附件、远程图片、HTML清洗、排版、重复去重、编号内容冲突、网络结果不确定时禁止重复新增。
- 在自有收件箱使用 IMAP APPEND 插入明确标记的合成邮件，不是从 Gmail 实际发送，也未向外部收件人发信。两份相同 article_id 被一次 n8n 执行成功处理，服务记录 created 与 already_created 各一次。
- 微信 draft/get 验证测试草稿标题、封面media_id、微信域名配图、strong及table正文。服务重启后同一内容仍返回 already_created；未认证私有请求返回401。
